## 2026-06-17 — Update (BMAD party-mode debate + OpenAlgo research)

Three party-mode rounds (real subagents per persona) plus a web-research detour, then folded into the spec.

**Round 1 — value-add features** (Victor, Dr. Quinn, Winston, John). Strong cross-agent convergence on a missing *substrate*: durable write-ahead intent log, clock/time abstraction, safe-start cold-boot gate, "connected-but-mute" + process self-health watchdogs, adversarial fake broker + adapter conformance kit, margin/SPAN shock simulation, push heartbeat + EOD reconciliation report. John held scope discipline (refuse strategy logic, GUI, more brokers, smart order routing; question multi-account at MVP).

**Round 2 — the 7 open questions** (Winston, Amelia, Murat — near-unanimous). Resolved → captured in new companion `technical-architecture.md` D1–D8:
- D1 Persistence: fsync'd append-only intent log (durable truth) + SQLite WAL projection. Not Postgres at single-VPS baseline.
- D2 Concurrency: synchronous safety core + threads at I/O edges; no asyncio in core.
- D3 Multi-account: one OS process per account + thin supervisor.
- D4 Runtime/packaging: Python 3.11+, PEP 621 wheel, adapters as extras, hashed lockfile. (Distribution public/private deferred.)
- D5 Alerts: Telegram + generic webhook + dead-man's-switch heartbeat; email deferred.
- D6 Static-IP: enforce safe-start egress-IP gate, document obligation, never claim to enforce the regulation.
- D8 Operator surface: library + thin CLI + localhost health endpoint, read-only except `kill`.

**Round 3 — product vs self-infrastructure** (Mary, Victor, John). Verdict: **staged**. Build the reliability library now; ship the tamper-evident hash-chained signed ledger as a *system-of-record foundation* (nearly free atop the intent log), NOT a billed product; defer all third-party proof tooling (dispute packet, external verifier, pricing) gated on usage telemetry + independent anchoring. Victor conceded "price the proof as the product" is dead. Mary's load-bearing finding: a self-hosted, self-signed log proves *consistency, not truth*; regulated buyers (PMS/AIF) can't use an operator-controlled record as their system of record. Distribution working assumption: open-core public PyPI.

**OpenAlgo research (web-verified):** OpenAlgo is a self-hosted **AGPL-v3** full-stack connectivity *platform* (Flask+React, REST/WebSocket, 24–30+ brokers, official Python SDK). It solves broker *connectivity*, not the execution-*safety* core. **User decision: Direct adapters only (D7)** — no OpenAlgo runtime dependency; keeps embedded-library/process-per-account architecture and the no-AGPL/open-core option intact.

**Spec changes applied:** +`technical-architecture.md` companion; +CAP-26…CAP-32 (intent log, clock/stall, safe-start gate, liveness/self-health watchdogs, tamper-evident ledger+EOD report+heartbeat, fake broker+conformance kit, margin/SPAN shock sim); +7 constraints (fsync-before-send, sync core, process-per-account, safe-start gate, tamper-evident-but-not-legal-proof, direct-adapters/no-OpenAlgo); +3 non-goals (not built on OpenAlgo, no third-party proof tooling in MVP, no claim of legal standing); 7 original open questions resolved → 3 new (positioning/distribution, target segment, independent anchoring); MVP lists + product-positioning section in `scope-and-phasing.md`; ledger/heartbeat/self-health sections in `resilience-and-reconciliation.md`; 10 glossary terms.

CAP-26…CAP-32 each carry intent + testable success; new constraints all rule something out; non-goals remain explicit; the 7 resolutions and the staged-product/OpenAlgo decisions are preserved across SPEC.md + `technical-architecture.md` + `scope-and-phasing.md` + decision log. ## 2026-06-17 — Update (gap caught: instrument-master lifecycle)

User flagged that periodic instrument-list download was not owned. Confirmed gap: the spec consumed instrument-derived data (lot/tick/freeze/expiry in the validation gate, "fetch instruments" as a safe read, "invalid symbol" error) but had **no first-class capability for the instrument/scrip master lifecycle**. Real risk in Indian markets: the F&O master changes daily (new strikes/weekly expiries; expired contracts drop), and a stale master → wrong lot/tick/freeze, untradeable new strikes, or attempts on expired contracts; instrument tokens also drive order placement + WebSocket subscription.

**Added CAP-33** (instrument-master lifecycle: scheduled daily refresh before first trade, restart-surviving cache, broker-neutral symbol↔token resolution, derived contract metadata, staleness gating, new/expired-contract handling, refresh-failure degradation). Threaded into: CAP-28 safe-start gate (fresh master is a safe-start check) + new constraint (no trading on a stale/unresolved master; master is the single source of lot/tick/freeze/expiry); `resilience-and-reconciliation.md` (new lifecycle section); `risk-controls.md` (gate sources values from current master); `scope-and-phasing.md` (MVP must-have + 3 production-checklist items); `glossary.md` (instrument master, instrument token).

**Self-validate:** PASS — CAP-33 has intent + testable success; constraint rules out trading on stale data; preserved across SPEC + 4 companions + log. Open-question count unchanged (3).
